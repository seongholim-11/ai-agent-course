## 학습 목표

- 이력서를 "무엇을 썼다"가 아니라 "무엇을 만들어 얼마나 개선했다"로 쓴다
- 면접 질문 은행의 모든 질문에 2분 안에 구조화된 답을 한다
- 에이전트 시스템 디자인 면접을 45분 안에 진행한다
- 라이브 코딩으로 에이전트 루프와 도구를 30분 안에 구현한다

## 이력서

### 프로젝트 항목 쓰는 법

이력서를 읽는 사람이 알고 싶은 것은 "이 사람이 **무슨 도구를 써봤나**"가 아니라 "이 사람이 **무엇을 해냈나**"입니다. 같은 프로젝트도 쓰는 방식에 따라 완전히 다르게 보입니다.

나쁜 예:

> LangGraph, MCP, Langfuse를 활용한 멀티 에이전트 리서치 시스템 개발

이 문장에서 알 수 있는 건 기술 이름뿐입니다. 같은 문장을 쓴 지원자가 수백 명입니다.

좋은 예:

> **Report Generation Agent** (Python, LangGraph, MCP, Langfuse, Docker) · GitHub 링크 · 데모 링크
> - Orchestrator–Worker 구조로 병렬 리서치를 구현해 보고서 생성 시간을 싱글 에이전트 대비 58% 단축
> - 단계별 모델 분리와 프롬프트 캐시 구조 개선(적중률 31% → 78%)으로 보고서당 비용 $0.91 → $0.38, 품질 유지(50문항 평가, judge-사람 일치율 0.86)
> - 체크포인트 기반 재개와 멱등 도구로 워커 강제 종료 20회 시험에서 완료율 100%, 중복 부수효과 0건
> - 평가 CI를 구축해 프롬프트·모델 변경 PR의 회귀를 자동 차단

공식은 **동사 + 무엇을 + 어떻게 + 수치 결과**입니다. 기술 이름은 프로젝트명 옆 괄호에 모아두고, 각 줄의 주인공은 **성과**가 되게 합니다. 그리고 각 줄이 서로 다른 역량(설계, 비용, 신뢰성, 평가)을 보여주게 고르면 한 프로젝트로 여러 축을 증명할 수 있습니다.

주의할 점: 이력서에 쓴 모든 숫자는 면접에서 "그거 어떻게 쟀어요?"라는 질문을 받습니다. **어떻게 측정했는지 설명할 수 있는 숫자만** 쓰세요. 14주차부터 평가 세트를 만든 이유가 여기 있습니다.

### 기술 스택 섹션

[기술 스택 체크리스트](../../interview/question-bank/#기술-스택-체크리스트) 기준으로 **직접 써서 결과를 낸 것만** 적습니다. 튜토리얼만 따라 해본 기술을 적으면, 면접관이 그 기술로 깊게 물어볼 때 바로 드러납니다. 면접관은 적힌 모든 것을 물어볼 수 있다고 생각하세요. 열 개를 얕게 적는 것보다 다섯 개를 깊게 설명할 수 있는 게 낫습니다.

## 면접 유형별 준비

### 1. 개념·경험 질문

[면접 질문 은행](../../interview/question-bank/)과 각 주차의 면접 질문 전부가 범위입니다. 읽고 고개를 끄덕이는 것과 입으로 설명하는 것은 전혀 다릅니다. 연습 방법:

1. 답을 펼치기 전에 **소리 내어** 2분 안에 답한다. 녹음을 추천합니다. 다시 들어보면 "음…"이 얼마나 많은지, 결론이 어디 있는지 보입니다.
2. 모범 답안과 비교해 빠진 핵심을 메모한다.
3. 내 프로젝트 경험을 한 문장 이상 섞어 답하는 연습을 한다. "저는 실제로 ○○에서 이렇게 했고 수치가 이렇게 바뀌었습니다." 교과서 같은 답보다 경험이 섞인 답이 훨씬 강합니다.

답의 구조는 **결론 먼저 → 이유 2~3개 → 내 경험 → 트레이드오프** 순이 좋습니다. 예: "멀티 에이전트는 독립적인 넓은 탐색에만 씁니다(결론). 이유는 ~이고(이유), 제 프로젝트에서는 ~였습니다(경험). 다만 ~한 경우는 오히려 나쁩니다(트레이드오프)."

각 주차 페이지 하단의 **💡 이해 완료** 버튼은 그 주의 면접 질문에 답을 보지 않고 이렇게 설명할 수 있을 때 누르세요.

### 2. 시스템 디자인

"고객센터 에이전트를 설계해보세요"처럼 정답 없는 설계 문제를 45분 동안 면접관과 대화하며 푸는 면접입니다. [시스템 디자인 면접](../../interview/system-design/) 페이지의 진행 순서와 연습 문제 4개로 연습합니다. 혼자 머릿속으로만 하면 시간 배분이 안 되니, 친구나 스터디원과 45분 모의 면접을 2회 이상 하세요.

### 3. 라이브 코딩

면접관 앞에서 30~40분 안에 코드를 짜는 면접입니다. 자주 나오는 형태:

- 도구 2~3개를 가진 에이전트 루프를 SDK로 구현 (4주차, 30분)
- 간단한 RAG: 문서 청킹 → 임베딩 → 코사인 유사도 검색 → 답변 (6주차, 40분)
- 주어진 에이전트의 버그 찾기 (tool_result 누락, 무한 루프, async 안의 블로킹 호출)
- 평가 함수 작성: 주어진 출력들로 정확도와 신뢰구간 계산 (14주차)

연습: **아무것도 보지 않고** 4주차 루프를 30분 안에 다시 짜보세요. 두 번 하면 손에 익습니다. 코드를 짜면서 "여기는 오류를 결과로 돌려줘야 모델이 복구할 수 있어서…"처럼 **이유를 말로 설명하는 연습**도 함께 하세요. 라이브 코딩은 정답보다 생각하는 과정을 봅니다.

### 4. 과제 전형

일부 회사는 2~7일짜리 집 과제를 줍니다. 이 코스의 습관이 그대로 통합니다. **요구사항 확인 → 가장 단순한 동작 버전 → 평가 세트로 측정 → 개선 → README에 설계 결정과 한계 정리.** 기능을 많이 넣는 것보다 "어떻게 측정했고, 왜 이렇게 설계했고, 무엇이 부족한지"를 설명하는 것이 점수를 가릅니다.

### 5. 컬처·협업

기술 면접 외에 일하는 방식을 묻는 질문도 나옵니다. "비개발자의 요구사항을 AI 기능으로 옮긴 경험", "AI가 틀렸을 때 사용자에게 어떻게 알릴지", "AI 기능 출시 여부를 데이터로 판단한 경험"이 자주 나옵니다. 국내 공고에서도 비기술 직군과의 소통 능력과 실행 중심 사고를 요구하는 경우가 많습니다. 24주 동안의 회고 메모에서 이야깃거리를 미리 골라두세요.

## 지원 전략

- **검색어를 넓게:** 공고는 "AI Agent Engineer" 외에 "AI Engineer", "LLM Engineer", "Backend Engineer(AI)", "ML Engineer(LLM)", "AI 서비스 개발"로도 올라옵니다. 같은 일을 회사마다 다른 이름으로 부릅니다.
- **공고에 맞춰 순서 바꾸기:** 공고의 주요 업무를 보고, 대표 프로젝트 중 가장 가까운 것을 이력서 맨 위에 둡니다. 고객센터 자동화 회사라면 RAG CS 챗봇을, 사내 자동화 회사라면 MCP 프로젝트를 먼저.
- **경력 요건이 있어도 지원:** 핵심 업무와 겹치는 프로젝트가 있으면 지원하고, 자기소개에 "운영 수준의 평가·관측·보안까지 직접 구현했다"를 명확히 씁니다. 많은 경력자도 아직 이 부분을 체계적으로 해보지 못했습니다.

## 실습 과제

- [ ] 이력서 프로젝트 항목 3개를 위 형식으로 작성
- [ ] 질문 은행 전 문항 녹음 연습 1회, 약한 질문 10개 2회
- [ ] 시스템 디자인 모의 면접 2회 (피드백 기록)
- [ ] 라이브 코딩: 에이전트 루프 30분, RAG 40분 각 1회
- [ ] 지원할 공고 10개 목록과 각 공고에 맞춘 이력서 버전

## 마무리

24주를 끝냈다면, 에이전트를 **만들고, 측정하고, 지키고, 운영하는** 경험을 모두 해본 것입니다. 이건 2026년 기준으로 많은 경력자도 아직 체계적으로 해보지 못한 일입니다. 수치와 실패 기록이 여러분의 가장 강한 무기입니다.
