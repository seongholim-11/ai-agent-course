## 채용 담당자는 무엇을 보는가

신입 대상 AI 엔지니어 공고는 6% 남짓입니다. 경력자와 경쟁하려면 포트폴리오가 **"이 사람은 실제 서비스를 운영할 수 있다"**는 증거여야 합니다. 차별화되는 순서:

1. **측정된 결과:** "정답률 87%(50문항, 95% CI 75~94%), 요청당 $0.011, p95 6.2초"
2. **실패와 개선의 기록:** "하이브리드 검색으로 Recall@5 0.62 → 0.81, 제품 코드 질문에서 효과가 컸다"
3. **설계 근거:** "멀티 에이전트를 쓴 이유와 쓰지 않은 부분"
4. **운영 요소:** 평가 CI, 트레이싱, 보안 테스트, 비용 통제, 재개 가능성
5. 동작하는 데모(공개 URL 또는 영상)

"LangGraph로 멀티 에이전트 챗봇을 만들었습니다"만 있는 포트폴리오는 수백 개입니다.

## 핵심 작업

### 1. 대표 프로젝트 고르기

[포트폴리오 프로젝트](../../projects/overview/) 5개 중 **1번(Report Generation Agent)과 5번(평가·관측 파이프라인)은 필수**, 나머지 하나는 지원 회사의 도메인에 맞춰 고릅니다(커머스·CS면 2번, B2B SaaS·사내 자동화면 3번, 데이터 조직이면 4번).

### 2. 아키텍처 다이어그램

박스와 화살표 수준이면 충분합니다. 중요한 것은 **데이터 흐름, 상태 저장 위치, 신뢰 경계(외부 콘텐츠가 들어오는 곳), 사람 승인 지점**이 보이는 것입니다. Mermaid로 저장소에 넣으면 수정이 쉽습니다.

### 3. 데모 영상 (2~3분)

1. 문제와 사용자(15초)
2. 실제 사용 장면: 입력 → 진행 이벤트 스트리밍 → 결과(60초)
3. 트레이스 화면에서 내부 동작 보여주기(30초)
4. 평가 리포트와 핵심 수치(30초)
5. 설계에서 가장 어려웠던 결정 하나(15초)

### 4. 코드 정리

- 비밀이 커밋 이력에 없는지 확인(`git log -p | grep -i "sk-"`, gitleaks)
- `docker compose up` 한 줄 실행, `.env.example` 제공
- 테스트와 평가가 CI에서 초록색
- 실습 주차 폴더(weeks/)는 별도 저장소로 분리하거나 정리해 대표 프로젝트가 묻히지 않게

<details>
<summary>포트폴리오 프로젝트에서 가장 어려웠던 점은?</summary>

답변 구조: 상황 → 문제(수치) → 시도한 것(실패 포함) → 해결 → 결과(수치) → 배운 것. 예: "리서치 에이전트의 오케스트레이터 컨텍스트가 12만 토큰까지 커져 후반 품질이 떨어졌습니다. 처음엔 compaction을 넣었는데 인용 정보가 요약에서 사라져 인용 정확도가 81%로 떨어졌습니다. 워커 결과를 파일로 저장하고 경로와 3줄 요약만 넘기도록 바꾸자 컨텍스트가 2.3만 토큰으로 줄고 인용 정확도가 94%가 되었습니다. 컨텍스트 관리에서는 요약보다 외부화와 격리가 정보 손실이 적다는 걸 배웠습니다."
</details>
