## 한 주를 보내는 방법

주 15~20시간을 기준으로 합니다. 시간의 **70% 이상은 직접 만드는 데** 쓰세요. 강의와 글은 방향을 잡는 용도입니다.

<Steps>

1. **월 – 개념 (3~4시간):** 주차 페이지의 "핵심 개념"과 "심화"를 읽고, 원본 강의의 해당 파트를 1.25~1.5배속으로 듣습니다. 코드는 눈으로만 보지 말고 직접 타이핑합니다.

2. **화~목 – 실습 (8~10시간):** "실습 과제"의 시작 코드에서 출발해 요구사항을 하나씩 채웁니다. 막히면 30분 고민한 뒤 공식 문서를 보고, 그다음에 코딩 에이전트에게 묻습니다.

3. **금 – 측정 (2~3시간):** 실습 결과를 "채점 기준"으로 스스로 평가합니다. 숫자(정답률, 비용, 지연)를 남기는 것이 핵심입니다.

4. **토 – 정리 (2시간):** 면접 질문에 답을 펼치기 전에 먼저 소리 내어 답해봅니다. 회고 메모에 "실패 → 원인 → 해결 → 수치"를 적고, 결과물을 GitHub에 push합니다.

</Steps>

</Aside>

## 실습 저장소를 하나로 관리하기

24주 실습을 저장소 하나(모노레포)에 모으면 포트폴리오로 그대로 쓸 수 있습니다. 구조는 [개발 환경 세팅](../setup/)을 참고하세요.

## 진도, 메모, 하이라이트 저장

- 주차 페이지 하단의 체크리스트와 회고 메모는 **이 브라우저의 localStorage**에 저장됩니다. 서버로 전송되지 않습니다.
- **하이라이트:** 본문을 드래그하면 형광펜 색(노랑·초록·파랑·분홍)이 뜹니다. 색을 누르면 저장되고, 하이라이트를 클릭하면 색을 바꾸거나 삭제할 수 있습니다. 하이라이트도 페이지별로 이 브라우저에 저장됩니다.
- 다른 기기나 브라우저로 옮기려면 상단 헤더의 GitHub 아이콘 왼쪽에 있는 **내보내기(↓)** 버튼으로 JSON을 저장하고, 옮긴 곳에서 **불러오기(↑)** 버튼으로 불러오세요. 진도·메모·하이라이트가 모두 포함됩니다. [진도 대시보드](../../dashboard/)에서도 같은 기능을 쓸 수 있습니다.
- 시크릿 창이나 사이트 데이터 삭제 시 지워질 수 있으니 주기적으로 내보내기를 권합니다.

## 완료의 기준

체크리스트는 "읽었다"가 아니라 **"만들었다, 측정했다, 설명할 수 있다"** 수준으로 체크합니다. 각 Phase의 완료 기준을 통과하지 못했다면 다음 Phase로 넘어가지 말고 실습을 보강하세요.
