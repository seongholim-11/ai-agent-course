## 한 줄 정의

사용자가 주제와 요구사항(분량, 독자, 관점)을 주면, 질문을 명확히 하고, 목차를 설계하고, 하위 주제를 병렬로 조사하고, 섹션을 작성·통합하고, 인용을 검증해 **출처가 달린 한국어 보고서**를 만든다.

## 아키텍처

```
POST /jobs ─▶ Queue ─▶ Worker
                          │
       ┌──────────────────┴──────────────────────────────────────┐
       │ LangGraph                                                │
       │  clarify ─▶ outline(Outliner) ─▶ Send×N ─▶ research(Researcher×N, 작은 모델)
       │                                              │ findings/*.md (파일)
       │                                              ▼
       │            reflect(빈 곳?) ──예──▶ 추가 research
       │                 │아니오
       │                 ▼
       │            write_sections(Writer, 섹션 병렬) ─▶ merge ─▶ cite_check ─▶ done
       └──────────── PostgresSaver 체크포인트 · Langfuse 트레이스 ─────────┘
```

## 요구사항

### 기능

1. **명확화:** 주제가 모호하면 질문 최대 3개(interrupt). 사용자가 건너뛰면 합리적 가정으로 진행하고 가정을 보고서에 명시.
2. **목차 설계:** 구조화 출력(섹션 제목, 핵심 질문, 필요한 근거 유형).
3. **병렬 조사:** 섹션별 Researcher. 브리프에 범위·제외 범위·출력 형식·예산. 결과는 `findings/{section}.md`에 쓰고 상태에는 경로와 요약만.
4. **반성:** 섹션별 근거가 부족하면 1라운드 추가 조사.
5. **작성:** 섹션 병렬 작성 후 통합(문체·중복 정리).
6. **인용 검증:** 모든 수치·주장에 [n] 인용, 출처 URL이 실제로 그 내용을 담고 있는지 별도 단계에서 확인. 실패 시 해당 문장 수정.
7. **결과물:** 마크다운 + PDF(선택), 출처 목록.

### 운영 (차별화 포인트)

- 작업 API(`/jobs`, SSE 이벤트, 취소), 워커 분리, 체크포인트 재개, 멱등 도구 (21주차)
- 단계별 모델 분리, 캐시 구조, 비용 예산 (19주차)
- 트레이싱과 비용 대시보드 (15주차)
- 외부 웹 콘텐츠는 untrusted로 표시, Researcher에게 외부 전송 도구 없음 (18주차)

## 평가

| 지표 | 측정 방법 |
| --- | --- |
| 품질 | 루브릭 judge(포괄성, 정확성, 구조, 독자 적합성) 기준별 PASS/FAIL, 사람 20건 대조 |
| 인용 정확도 | 무작위 인용 50개를 사람이 확인 + 자동 검증기 결과 |
| 비용·시간 | 보고서당 p50/p95 |
| 신뢰성 | 워커 강제 종료 game day 10~20회 완료율, 중복 부수효과 |
| 비교 기준선 | 같은 주제를 싱글 에이전트(턴 40)로 생성했을 때 |

평가 주제 10~20개: 기술 비교(예: 벡터 DB 4종), 시장 동향, 정책 요약 등 다양하게.
