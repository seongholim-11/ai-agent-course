24주 동안의 실습이 모여 아래 5개 프로젝트가 됩니다. 아래 다섯 개 중 **세 개를 깊게** 완성하는 편이 여러 개를 얕게 만드는 것보다 낫습니다. **1번과 5번은 필수**이고, 나머지 하나는 지원하는 도메인에 맞춰 고르세요.

| 프로젝트 | 보여주는 역량 | 면접에서 보일 수치 | 연결 주차 |
| --- | --- | --- | --- |
| [1. Report Generation Agent](../report-agent/) (필수) | 멀티 에이전트, 컨텍스트 관리, 신뢰성 | 보고서당 비용·시간, 인용 정확도, 장애 시 완료율 | 8, 11–13, 19–21 |
| [2. Agentic RAG CS 봇](../rag-cs-bot/) | RAG, 메모리, HITL | 정답률, 환각률, 거절 정확도, 응답 시간 | 6, 7, 13 |
| [3. 사내 MCP 서버 + 자동화 에이전트](../mcp-automation/) | MCP, OAuth, 보안 | 작업 성공률, 인젝션 방어율 | 9, 17–18 |
| [4. Text2SQL 데이터 분석 에이전트](../text2sql-agent/) | 도구 설계, 샌드박스, 정확도 | SQL 실행 정확도, 실패 복구율 | 4, 10, 18 |
| [5. 평가·관측 파이프라인](../eval-pipeline/) (필수) | Evals, LLMOps, CI | judge-사람 일치율, 회귀 차단 사례, 모델 교체 비교 | 14–16 |

## 모든 프로젝트의 공통 요건

- [ ] 공개 GitHub 저장소, `docker compose up` 한 줄 실행, `.env.example`
- [ ] 아키텍처 다이어그램과 설계 결정 이유(왜 이 구조인가, 무엇을 하지 않았나)
- [ ] 평가 세트와 결과표(반복 횟수, 신뢰구간), 실패 사례 분석
- [ ] 비용·지연 수치와 최적화 전후 비교
- [ ] 트레이싱 연결
- [ ] 보안 고려(최소 권한, 승인, 입력 검증) 섹션
- [ ] 2~3분 데모 영상
